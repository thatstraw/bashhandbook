= Pipelines and Redirections

== Pipelines in Bash

Pipelines are one of Bash's most powerful features, allowing you to connect commands together so that the output of one becomes the input of the next. This chaining mechanism enables complex data processing to be written in a clean and efficient way.

=== What Is a Pipeline?

A pipeline is a sequence of commands connected by the pipe symbol (`|`). Bash sends the standard output (stdout) of the command on the left side of the pipe as standard input (stdin) to the command on the right.

.Syntax
[source,bash]
----
command1 | command2 | command3
----

Each command processes the data it receives and passes it along the chain. This allows for complex processing in one line.

=== Basic Example

Count the number of lines containing the word "error" in a log file
[source,bash]
----
grep "error" log.txt | wc -l
----

Here's what happens:

* `grep "error" log.txt` finds all lines with the word "error".
* `wc -l` counts how many lines `grep` returned.

=== Filtering and Transforming Data

Pipelines are especially powerful when combined with text processing tools like `grep`, `sed`, `awk`, `cut`, and `sort`.

Replace the word "failure" with "success" in lines that contain "error"
[source,bash]
----
grep "error" log.txt | sed 's/failure/success/g'
----

What's happening here:

* `grep` filters lines containing "error".
* `sed` replaces every instance of "failure" with "success" in those lines.

=== Combining Pipelines with Redirection

You can combine pipelines with redirection operators to save or read from files.

Save the output of a pipeline to a file
[source,bash]
----
command1 | command2 > output.txt
----

Feed input to a pipeline from a file
[source,bash]
----
command1 < input.txt | command2
----

You can also redirect standard error:

Redirect stderr to a file while piping stdout
[source,bash]
----
command1 2> errors.txt | command2
----

=== A quick practical example

Extract and deduplicate log information
[source,bash]
----
grep "error" log.txt | awk '{print $3, $5}' | sort | uniq > unique_errors.txt
----

Step-by-step breakdown:

* `grep "error" log.txt` filters lines with "error".
* `awk '{print $3, $5}'` selects the 3rd and 5th fields from each line.
* `sort` organizes the lines alphabetically.
* `uniq` removes duplicates.
* `>` writes the result to `unique_errors.txt`.

Pipelines let you:

* Combine multiple commands for cleaner, more expressive shell scripts.
* Pass data from one tool to another seamlessly.
* Process and transform large datasets without temporary files.

Use them whenever you find yourself doing multiple steps on the same data — they're the glue that makes shell scripting flexible and composable.

== Redirections in Bash

When working with input and output in Bash, everything is treated as a stream of data. These streams are managed using **file descriptors**. By default, three file descriptors are always open in a shell session:

[cols="1,1,4",options="header"]
|===
| File Descriptor | Abbreviation | Description
| `0` | `STDIN` | Standard input. This is usually your keyboard. When you use the input redirection symbol (`<`), Bash reads input from a file as if it were typed at the keyboard.
| `1` | `STDOUT` | Standard output. This is usually your terminal screen. When you use the output redirection symbol (`>`), Bash writes the output to a file instead of the screen.
| `2` | `STDERR` | Standard error. Like `STDOUT`, this normally writes to your screen, but is used specifically for error messages. You can redirect it using `2>` to capture error output separately.
|===

[TIP]
====
Unless explicitly closed, file descriptors always point to something—typically your terminal when Bash starts.

In addition to `0`, `1`, and `2`, you can open and close custom file descriptors (`3`, `4`, `5`, ...), and even duplicate them to point to the same location. These are powerful tools for advanced scripting and redirection techniques.
====

=== Redirection Operators

Redirection in Bash allows you to control where input comes from and where output goes. Below is a comprehensive list of redirection operators and what they do.
[cols="1,3", options="header"]
|===
| Redirection
| Description

| `command > file`
| Redirect the standard output (stdout) of a `command` to a specified file. Same as `command 1> file`.

| `command 2> file`
| Redirect the standard error (stderr) of a `command` to a specified file.

| `command >> file`
| Append stdout of a `command` to a specified file without overriding existing data.

| `command 2>> file`
| Append stderr of a `command` to a specified file without overriding existing data.

| `command &> file`
| Redirect both stdout and stderr of a `command` to a file. Same as `command > file 2>&1`, but not `command 2>&1 > file`.

| `command > /dev/null`
| Discard stdout of a `command`. `/dev/null` discards all data written to it.

| `command 2> /dev/null`
| Discard stderr of a `command`.

| `command &> /dev/null`
| Discard both stdout and stderr of a `command`. Same as `command > /dev/null 2>&1`.

| `command < file`
| Redirect the contents of a file to stdin of a `command`. Same as `command 0< file`.

| `command << EOL`
| Redirect multiple lines to stdin using a here-document. Ends when a line with only `EOL` is found.

| `command <<- EOL`
| Same as `<<` but strips leading tab characters from the input.

| `command <<< 'string'`
| Use a here-string to redirect input from a single string.

| `command <<< $word`
| Same as above but using a variable.

| `command >\| file`
| Overrides the `noclobber` shell option to force file overwrite.

| `exec 2> file`
| Redirect stderr of all commands to a file.

| `exec > file`
| Redirect stdout of all commands to a file.

| `exec 3< file`
| Create custom file descriptor (3) for reading from a file.

| `exec 3> file`
| Create custom file descriptor (3) for writing to a file.

| `exec 3<> file`
| Create custom file descriptor (3) for both reading and writing.

| `exec 3>&-`
| Close the created file descriptor.

| `exec 4<&3`
| Make file descriptor 4 a copy of file descriptor 3.

| `exec 4>&3-`
| Copy file descriptor 3 to 4 and close file descriptor 3.

| `echo "foo" >&3`
| Write to custom file descriptor 3.

| `cat <&3`
| Read from custom file descriptor 3.

| `exec 3<> /dev/tcp/host/port`
| Open a TCP connection. Bash feature only.

| `exec 3<> /dev/udp/host/port`
| Open a UDP connection. Bash feature only.

| `(command1; command2) > file`
| Redirect stdout from multiple commands to a file using a subshell.

| `{ command1; command2; } > file`
| Redirect stdout from multiple commands to a file without subshell. Faster.

| `command < <(command1)`
| Redirect stdout of `command1` to an anonymous pipe and pass to `command`.

| `command < <( command1 )`
| Same as above. Example: `diff <(find /path1 \| sort) <(find /path2 \| sort)`

| `command < <(command1) < <(command2)`
| Redirect output of two commands to anonymous pipes and pass to another command.

| `command1 >(command2)`
| Run `command2` with stdin connected to a named pipe and pass filename to `command1`.

| `command1 > >(command2)`
| Run `command2` with stdout from `command1` through a named pipe.

| `command1 \| command2`
| Redirect stdout of `command1` to stdin of `command2`.

| `command1 \|& command2`
| Redirect stdout and stderr of `command1` to stdin of `command2`. (Bash 4.0+)

| `command \| tee file`
| Redirect stdout of `command` to both a file and screen.

| `exec {filew}> file`
| Open file for writing using a named file descriptor (`filew`). Bash 4.1+.

| `command 3>&1 1>&2 2>&3`
| Swap stdout and stderr of a `command`.

| `cmd > >(cmd1) 2> >(cmd2)`
| Send stdout to `cmd1` and stderr to `cmd2`.

| `cmd1 \| cmd2 \| cmd3 \| cmd4; echo \${PIPESTATUS[@]}`
| Show exit codes of all piped commands.

|===
