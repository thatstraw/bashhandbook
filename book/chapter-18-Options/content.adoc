= Bash Options

Bash options are configuration settings that modify the behavior of the shell or a script. You can enable or disable these options using the `set` builtin.

There are two main syntaxes to control options:

- `set -o option-name` or `set -option-abbrev` to **enable** an option.
- `set +o option-name` or `set +option-abbrev` to **disable** an option.

To enable an option **only when running a script**, you can do:

[source,bash]
----
bash -o option-name script.sh
# or
bash -option-abbrev script.sh
----

[NOTE]
====
Options affect how scripts behave and are critical when building reliable, secure, and predictable shell scripts.
====

== Common Bash Options

[cols="1,1,3",options="header"]
|===
| Abbreviation | Name | Effect

| `-B` | brace expansion
| Enable brace expansion (e.g., `{a,b,c}` becomes `a b c`). This is on by default.

| `+B` | brace expansion
| Disable brace expansion.

| `-C` | noclobber
| Prevent overwriting files via output redirection. You can still override with `>|`.

| `-D` | — 
| Print double-quoted strings prefixed with `$` but **do not execute** commands. Used for debugging.

| `-a` | allexport
| Automatically export all variables as environment variables.

| `-b` | notify
| Notify when background jobs complete (not typically useful in scripts).

| `-c '...'` | —
| Read and execute commands from the given string instead of a script or stdin.

| — | checkjobs
| Warns about unfinished background jobs on shell exit. Enable with `shopt -s checkjobs`. Use with caution—it may hang!

| `-e` | errexit
| Exit the script if **any command** fails (non-zero exit status). Critical for robust scripting.

| `-f` | noglob
| Disable filename expansion (globbing) using wildcards like `*` and `?`.

| — | globstar
| Enable `**` for recursive globbing (e.g., `**/*.txt`). Enable with `shopt -s globstar`.

| `-i` | interactive
| Run the script in **interactive mode** (useful for REPL-like input).

| `-n` | noexec
| Don’t execute any commands—just check for syntax errors.

| `-o name` | —
| Enable the named shell option (like `pipefail` or `posix`).

| `-o posix` | POSIX mode
| Make Bash behave like a POSIX-compliant shell. Useful for portability.

| `-o pipefail` | pipe failure
| Make a pipeline return the exit code of the **first** failed command instead of the **last** one.

| `-p` | privileged
| Run the script with elevated privileges. Be very cautious with this!

| `-r` | restricted
| Enable **restricted mode**, limiting what the shell can do (e.g., no `cd` or `exec`).

| `-s` | stdin
| Read script input from stdin instead of a file.

| `-t` | onecmd
| Run just one command and exit.

| `-u` | nounset
| Treat **undefined variables** as errors and abort the script. Great for catching typos.

| `-v` | verbose
| Print each command to stdout **before** execution.

| `-x` | xtrace
| Print commands **and** their expanded arguments (useful for debugging).

| `-` | —
| End of options. Everything after this is treated as a positional parameter.

| `--` | —
| Unset all positional parameters. If arguments are given (`-- arg1 arg2`), positional parameters are set to them.
|===

[TIP]
====
You can combine multiple options in one go:

[source,bash]
----
set -eux  # Exit on error, treat unset variables as errors, print commands
----
====

== Additional Bash Options

Bash includes extra optional behaviors that aren't controlled with `set`, but with another builtin: `shopt`. This command lets you enable or disable various shell behaviors that are especially useful in scripting and interactive use.

=== The `shopt` Builtin

Use `shopt` to view or modify these shell options.

[source,bash]
----
shopt [-pqsu] [-o] <OPTION...>
----

[NOTE]
====
- Use `-s` to **set** an option  
- Use `-u` to **unset** an option  
- Use `-p` to **print** all shell options and their status (default)
- Use `-q` to **query** quietly (exit status only, no output)
- Use `-o` to restrict to options also used by `set`
====

[IMPORTANT]
====
If you run `shopt -s nullglob`, then glob patterns that don’t match anything will expand to nothing instead of staying as-is. This is extremely helpful to avoid errors in loops.
====

=== Exit Code Behavior

When you list or change options using `shopt`, the command sets an appropriate exit status:

- **0 (true)** if the operation was successful (or all options are enabled when queried).
- **1 (false)** if one or more options are disabled or an unknown option was referenced.

.Example: Enable nullglob
[source,bash]
----
shopt -s nullglob
----

=== shopt Options Summary

[cols="1,3",options="header"]
|===
| Flag | Meaning

| `-s`
| Set (enable) the specified option(s)

| `-u`
| Unset (disable) the specified option(s)

| `-p`
| Print all shell options and their status (default)

| `-q`
| Quiet mode. Exit status reflects whether all named options are enabled

| `-o`
| Restrict options to those also accepted by `set`
|===

== Additional Shell Options

These are some of the most useful options you can enable with `shopt -s` or disable with `shopt -u`:

[cols="1,3",options="header"]
|===
| Option | Description

| `autocd`
| Allows you to type a directory name directly to `cd` into it, without using the `cd` command.

| `cdspell`
| Automatically corrects small typos in `cd` directory names (e.g. transposed characters, missing/extra letters).

| `checkjobs`
| Prevents the shell from exiting if there are running or stopped jobs. You must exit twice to leave.

| `dirspell`
| Enables spelling correction for directory names used in glob patterns.

| `dotglob`
| Makes glob patterns like `*` also match hidden files (those beginning with a dot).

| `nullglob`
| Causes globs that don't match any files to expand to nothing instead of remaining as-is.

| `failglob`
| Makes Bash throw an error if a glob pattern fails to match any files.

| `nocaseglob`
| Makes glob matching case-insensitive.

| `globstar`
| Enables the `**` pattern to recursively match files and directories.

|===

[TIP]
====
To enable multiple options at once, you can list them:

[source,bash]
----
shopt -s dotglob nullglob globstar
----
====

[INFO]
====
For a full list of `shopt` options, check the official Bash manual: https://www.gnu.org/software/bash/manual/html_node/The-Shopt-Builtin.html
====


== POSIX Character Classes (for BRE/ERE)

POSIX character classes make your regular expressions more portable and readable by replacing common character ranges with symbolic names. These are especially useful inside `[` and `]` brackets when working with tools like `grep`, `sed`, and `awk`.

[cols="1,2,3",options="header"]
|===
| Class | Equivalent | Description

| `[[:alnum:]]`
| `[0-9A-Za-z]`
| Matches any alphanumeric character: digits and letters

| `[[:alpha:]]`
| `[A-Za-z]`
| Matches any letter, regardless of case

| `[[:blank:]]`
| `[ \t]`
| Matches a space or a tab

| `[[:digit:]]`
| `[0-9]`
| Matches any single digit

| `[[:graph:]]`
| `[[:alnum:][:punct:]]`
| Matches any visible character (excluding space)

| `[[:lower:]]`
| `[a-z]`
| Matches any lowercase letter

| `[[:print:]]`
| `[ -~]`
| Matches any printable character, including space

| `[[:punct:]]`
| `[!"#$%&'()*+,-./:;<=>?@[\]^_\`{|}~]`
| Matches any punctuation character

| `[[:space:]]`
| `[ \t\n\v\f\r]`
| Matches any whitespace character (space, tab, newline, etc.)

| `[[:upper:]]`
| `[A-Z]`
| Matches any uppercase letter

| `[[:word:]]`
| `[0-9A-Za-z_]`
| Matches word characters (like those used in variable names)

| `[[:xdigit:]]`
| `[0-9A-Fa-f]`
| Matches hexadecimal digits

| `[[:<:]]`
| `\b(?=\w)`
| Matches the start of a word (GNU extension)

| `[[:>:]]`
| `\b(?<=\w)`
| Matches the end of a word (GNU extension)

| `[[:ascii:]]`
| `[\x00-\x7F]`
| Matches ASCII characters (codes 0–127)

| `[[:cntrl:]]`
| `[\x00-\x1F\x7F]`
| Matches control characters (non-printable)
|===

[IMPORTANT]
====
POSIX classes should only be used inside bracket expressions, like `[[:digit:]]` rather than `[:digit:]`.
====

== Quantifiers

Quantifiers let you specify how many times a part of your regex should match. They are essential for writing flexible and powerful patterns.

[cols="1,3",options="header"]
|===
| Pattern | Description

| `?`
| Matches the preceding element zero or one time

| `*`
| Matches the preceding element zero or more times

| `+`
| Matches the preceding element one or more times

| `[0-9]+`
| Matches one or more digits (0 through 9)

| `{m}`
| Matches the preceding element exactly `m` times

| `{m,n}`
| Matches the preceding element at least `m` times, but no more than `n` times

| `{m,}`
| Matches the preceding element `m` or more times

| `a*`
| Greedy: matches as many occurrences of `a` as possible

| `a*?`
| Lazy: matches as few as possible while still allowing the overall pattern to match

| `a*+`
| Possessive: matches as many as possible without backtracking

| `{,n}`
| Matches the preceding element up to `n` times
|===

== Groups and Ranges

Regular expressions support grouping, alternation, and ranges to match more complex patterns. These features are particularly useful when you're trying to match multiple possibilities in one go.

[cols="1,3",options="header"]
|===
| Pattern | Description

| `.`
| Matches any character except a newline (`\n`)

| `(a|b)`
| Matches either `a` or `b` (alternation)

| `(...)`
| Capturing group: groups part of the regex and remembers the match

| `(?:...)`
| Non-capturing group: groups part of the regex without capturing it

| `[abc]`
| Matches any single character: `a`, `b`, or `c`

| `[^abc]`
| Matches any character *except* `a`, `b`, or `c`

| `[a-q]`
| Matches any lowercase letter from `a` to `q`

| `[A-Q]`
| Matches any uppercase letter from `A` to `Q`

| `[0-7]`
| Matches any digit from `0` to `7`

| `\x`
| Refers to a previously matched sub-pattern (by number)
|===

== Pattern Modifiers

These modifiers tweak how the regex engine behaves when interpreting the pattern.

[cols="1,3",options="header"]
|===
| Modifier | Description

| `g`
| Global match: apply the regex to *all* matches in the input, not just the first

| `i`
| Case-insensitive matching

| `m`
| Treat input as multiple lines (affects `^` and `$` anchors)

| `s`
| Treat input as a single line (dot `.` will match newline too)

| `x`
| Ignore whitespace and allow comments in pattern (for readability)

| `e`
| Evaluate replacement as code (used in some `sed` variants)

| `U`
| Makes quantifiers ungreedy by default
|===

== Assertions

Assertions are zero-width conditions—meaning they don't consume characters but still affect matches. Think of them as invisible checks.

[cols="1,3",options="header"]
|===
| Assertion | Description

| `(?=...)`
| Positive lookahead: checks for a match *ahead* without consuming it

| `(?!...)`
| Negative lookahead: ensures a pattern is *not* ahead

| `(?<=...)`
| Positive lookbehind: checks for a pattern *behind* the current position

| `(?<!...)`
| Negative lookbehind: ensures a pattern *doesn't* exist behind

| `(?>...)`
| Atomic group: once matched, prevents backtracking

| `(?(cond)yes)`
| Conditional match (rare)

| `(?(cond)yes|no)`
| Conditional with else clause

| `(?# comment )`
| Inline comment (only supported in some engines)
|===

== String Replacement Variables

Used in tools like `sed`, Perl, and some `bash` string substitutions, these refer to portions of the original match.

[cols="1,3",options="header"]
|===
| Symbol | Description

| `$n`
| Contents of the nth capture group

| `$2`
| Second capture group (e.g. `xyz` in `/^(abc(xyz))$/`)

| `$1`
| First capture group (e.g. `xyz` in `/^(?:abc)(xyz)$/`)

| ``$````
| Part of the string *before* the match

| `$'`
| Part of the string *after* the match

| `$+`
| Last matched group

| `$&`
| Entire matched string
|===

== Escape Sequences

Some characters must be escaped to be interpreted literally or to represent invisible characters.

[cols="1,3",options="header"]
|===
| Sequence | Description

| `\\`
| Escape the next character

| `\Q`
| Begin literal mode (treat all characters literally)

| `\E`
| End literal mode (resume special character interpretation)
|===

[IMPORTANT]
====
Escaping is how you prevent special characters from acting like metacharacters. For example, to match a literal dot (`.`), use `\.` instead of `.`.
====

== Search for Lines That Start with a Word

[source,bash]
----
grep '^ERROR' /var/log/syslog
----

This command finds all lines in `/var/log/syslog` that start with the word `ERROR`.

- `^` is the regex anchor for the beginning of the line.
- This ensures it doesn't match lines where `ERROR` appears later in the line.

[NOTE]
====
Use quotes around patterns with special characters like `^` to prevent shell expansion.
====

== Match IP Addresses Using `grep`

[source,bash]
----
grep -Eo '([0-9]{1,3}\.){3}[0-9]{1,3}' access.log
----

- `-E` enables extended regex.
- `-o` prints only the matched portion, not the whole line.
- `([0-9]{1,3}\.){3}[0-9]{1,3}` matches typical IPv4 addresses.

[WARNING]
====
This matches numbers like `999.999.999.999`, which aren't valid IPs—but it's fine for quick parsing. Use stricter patterns for validation.
====

== Find Email Addresses in a Text File

[source,bash]
----
grep -Eo '[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}' newsletter.txt
----

This matches most standard email formats.

- `+` matches one or more of the preceding character set.
- `@` is literal.
- `[A-Za-z]{2,}` ensures domain extensions are at least 2 letters long.

== Replace Tabs with Commas Using `sed`

[source,bash]
----
sed 's/\t/,/g' input.tsv > output.csv
----

- `\t` matches tab characters.
- `s/old/new/g` is the basic `sed` substitution.
- This converts tab-separated files to comma-separated format.

== Print Lines That Don’t Contain a Pattern

[source,bash]
----
grep -vE 'DEBUG|TRACE' app.log
----

- `-v` inverts the match.
- `-E` allows extended regex, so you can use `|` to match multiple patterns.
- This filters out noisy log levels.

== Extract Usernames from `/etc/passwd`

[source,bash]
----
awk -F: '{ print $1 }' /etc/passwd | grep '^[a-z]'
----

- `awk -F:` sets the delimiter to `:`.
- `{ print $1 }` grabs the username field.
- `grep '^[a-z]'` filters for lowercase usernames only.
